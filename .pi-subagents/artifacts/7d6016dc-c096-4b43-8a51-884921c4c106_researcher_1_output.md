# Research: OpenAI translation-grading evaluation suite

## Summary

`5.6 luna high` is **not a documented OpenAI API model ID** and should be treated as invalid unless it is an application-specific alias translated before requests reach OpenAI. For the evaluation suite, use the Responses API with `text.format` structured outputs, collect nested usage details, account for automatic prefix caching, and use Batch only when asynchronous completion within 24 hours is acceptable.

Live web search was unavailable during this review, so current pricing and model availability should be revalidated against the cited official pages or `GET /v1/models` before release.

## Findings

1. **Blocker — `5.6 luna high` is not a verified OpenAI model ID**  
   Official IDs use names such as `gpt-4.1`, `gpt-4.1-mini`, `gpt-4o`, and versioned snapshots. No official model documentation identifies `5.6 luna high`; the spaces and “luna high” naming resemble a UI label or third-party alias rather than an OpenAI ID. Sending it directly should be expected to produce a model-not-found or access error.  
   Runtime availability is best checked with `GET /v1/models`, because the result reflects the authenticated project’s accessible models. The Models API list is not necessarily a statement that every returned model is suitable for Responses or structured outputs. [Models documentation](https://platform.openai.com/docs/models) [List models](https://platform.openai.com/docs/api-reference/models/list)

2. **High — Use Responses structured output through `text.format`, not Chat Completions’ `response_format` shape**  
   A raw Responses request uses a structure equivalent to:
   ```json
   {
     "model": "<verified-model-id>",
     "input": "...",
     "text": {
       "format": {
         "type": "json_schema",
         "name": "translation_grade",
         "strict": true,
         "schema": {
           "type": "object",
           "properties": {
             "winner": {
               "type": "string",
               "enum": ["a", "b", "tie"]
             },
             "score_a": {"type": "number"},
             "score_b": {"type": "number"},
             "explanation": {"type": "string"}
           },
           "required": ["winner", "score_a", "score_b", "explanation"],
           "additionalProperties": false
         }
       }
     }
   }
   ```
   Official SDK parsing helpers can return a parsed object, but integrations should still handle refusal and incomplete-response paths. Structured Outputs supports a subset of JSON Schema; strict schemas generally need explicit required properties and `additionalProperties: false`. The first request using a new schema may incur additional processing latency. [Structured Outputs guide](https://platform.openai.com/docs/guides/structured-outputs) [Responses API](https://platform.openai.com/docs/api-reference/responses/create)

3. **High — Token usage is nested and should not be inferred from text length**  
   Store at least:
   - `usage.input_tokens`
   - `usage.input_tokens_details.cached_tokens`
   - `usage.output_tokens`
   - `usage.output_tokens_details.reasoning_tokens`
   - `usage.total_tokens`

   Uncached input can be computed as `input_tokens - cached_tokens`. Reasoning tokens are included in output-token accounting rather than being an additional independent billing category. Parsers should tolerate absent detail objects or new detail fields, because fields can vary by model and feature. Also save `response.model`, since aliases may resolve to a different concrete model/version. [Responses object](https://platform.openai.com/docs/api-reference/responses/object)

4. **Medium — Prompt caching is automatic but requires exact shared prefixes**  
   Officially documented behavior includes:
   - Caching applies to prompts of at least **1,024 tokens**.
   - Cacheable lengths increase in **128-token increments**.
   - Cache hits require an exact prefix match.
   - Static instructions, examples, output schema, and common reference material should appear before per-example translation text.
   - Tools and structured-output schemas form part of the prefix.
   - Cache effectiveness is visible through `input_tokens_details.cached_tokens`.
   - `prompt_cache_key` can help group requests with a common prefix.
   - Default in-memory caches generally expire after approximately 5–10 minutes of inactivity and always within roughly one hour.
   - Supported models may offer extended retention through `prompt_cache_retention: "24h"`; support must be checked per model.

   Caching does not change the generated answer, but it can reduce latency and the billable cached-input rate. It is not a guarantee that every eligible request will hit a cache. [Prompt caching guide](https://platform.openai.com/docs/guides/prompt-caching)

5. **Medium — Batch offers price savings in exchange for asynchronous, unordered results**  
   The Batch API provides a documented **50% discount** relative to synchronous input and output rates, uses a separate rate-limit pool, and accepts a completion window of `24h`. Requests are uploaded as JSONL and results are retrieved from output/error files. Results should be joined by `custom_id`, not line position, because output ordering is not guaranteed.  
   It is appropriate for offline grading runs, regression suites, or dataset-scale comparisons. It is inappropriate for interactive side-by-side UI grading or jobs requiring a guaranteed completion time substantially below 24 hours. Expired, failed, or cancelled batches require reconciliation and retry logic. [Batch guide](https://platform.openai.com/docs/guides/batch)

6. **High — Cost calculation must distinguish uncached input, cached input, and output**  
   For rates stated per million tokens:
   ```text
   uncached_input = input_tokens - cached_tokens

   cost =
     uncached_input / 1_000_000 * input_rate
     + cached_tokens / 1_000_000 * cached_input_rate
     + output_tokens / 1_000_000 * output_rate
   ```
   Do not add reasoning tokens again when they are already included in `output_tokens`. Batch rates should be recorded separately rather than implementing a generic discount assumption in case OpenAI changes model-specific pricing.

7. **Official pricing examples, requiring release-time revalidation**  
   The following officially published standard API rates are useful baselines, in USD per 1M tokens:

   | Model | Input | Cached input | Output |
   |---|---:|---:|---:|
   | `gpt-4.1` | $2.00 | $0.50 | $8.00 |
   | `gpt-4.1-mini` | $0.40 | $0.10 | $1.60 |
   | `gpt-4.1-nano` | $0.10 | $0.025 | $0.40 |
   | `gpt-4o` | $2.50 | $1.25 | $10.00 |
   | `gpt-4o-mini` | $0.15 | $0.075 | $0.60 |
   | `o3` | $2.00 | $0.50 | $8.00 |

   Because the pricing page is mutable and live retrieval failed during this task, these should **not** be hard-coded without rechecking the official table. Store pricing as versioned configuration with an effective date. Fine-tuning, web search, containers, storage, and other tools can have separate charges. [Official API pricing](https://openai.com/api/pricing/)

8. **Recommended implementation controls**  
   - Validate configured models against an allowlist built from official documentation and a project-authenticated capability probe.
   - Keep UI labels separate from API IDs, e.g. `{label: "High quality", model: "gpt-4.1"}`.
   - Pin a documented snapshot where reproducibility is more important than automatic improvements.
   - Store prompt version, schema version, requested model, returned model, request ID, usage, and pricing-table version.
   - Randomize or blind candidate A/B ordering to reduce positional bias.
   - Run a small synchronous validation sample before submitting a full Batch job.

## Gaps

- The official pages could not be live-fetched; model availability and pricing therefore lack same-day verification.
- `GET /v1/models` requires credentials and was not executed. It should be run in the target OpenAI project because access varies by account, project, and model.
- The current application configuration was not inspected, so it is unknown whether `5.6 luna high` is translated by an internal gateway. It is invalid as a direct, publicly documented OpenAI ID, but could theoretically be a local alias.
- Pricing examples require a final check immediately before implementation or release.
