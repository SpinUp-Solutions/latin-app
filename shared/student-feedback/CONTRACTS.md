# Student feedback contracts

`shared/student-feedback/index.ts` is the browser, Next server, and Functions contract. It imports only Zod. Firestore collection names come from `shared/constants/firestore.ts`.

## Form and submit

- `submitFeedbackRequestSchema`: `{ sessionId, type, severity?, areas, otherAreaExplanation?, description, rating?, comments?, lessonId?, pageContext?, attachmentIds, diagnostics }`. `sessionId` and attachment IDs are UUIDs. `lessonId` is a Firestore document ID or `null`; page context is `{ pageId, pageIndex, revision }` or `null`. A page context requires a lesson.
- Type keys: `bug_report`, `feature_suggestion`, `general`. Severity keys: `blocking`, `major`, `minor`; severity is required only for bugs. Area keys: `lessons`, `exercises`, `vocabulary`, `dashboard`, `account`, `performance`, `other`. Area labels are `FEEDBACK_AREA_LABELS`. Selecting `other` requires `otherAreaExplanation`.
- Plain-text fields are trimmed at the edge. Description limit: 10,000 characters; comments: 5,000; Other explanation: 500. Rating is optional integer 1–5. Duplicate areas/attachment IDs are rejected.
- `diagnostics` permits only entry point, app version, browser, viewport, and route path without query or fragment. No actor, storage path, canonical metadata, or admin state may be supplied by the client.
- `createFeedbackSessionRequestSchema`: `{ sessionId }`; repeat with the same authenticated owner to recover. The report document ID equals the session ID. `reserveFeedbackAttachmentRequestSchema`: `{ attachmentId, originalName, contentType, sizeBytes }`.
- `GET /api/feedback/lessons` returns `feedbackLessonsResponseSchema`: `{ lessons: [{ id, title, revision }] }`. `revision` is the lesson's `version`, or zero for a legacy lesson without one. A selector change clears `pageContext`; the lesson player supplies `{ pageId, pageIndex, revision }` for its current page.

## Persisted documents

- `feedbackReportDocumentSchema`: strict `schemaVersion: 1`, `id`, `sessionId`, server `submitter`, original form fields, `areaFlags` (all seven booleans, matching `areas`), `lesson` snapshot or `null`, verified `attachments`, `diagnostics`, canonical ISO `createdAt`/`updatedAt`, `status`, resolution fields, independent archive fields, `stateRevision`. New report: `status: 'unresolved'`, resolution fields `null`, `archived: false`, archive fields `null`, revision `0`. `submitter.emailNormalized` is for exact server filtering; query `areaFlags.<area> == true` for area filtering. Student text remains immutable.
- `feedbackSessionDocumentSchema`: `id`, `ownerUid`, status (`open`, `submitted`, `cleanup`, `cancelled`, `expired`), ISO audit timestamps, numeric `expiresAtMs`, active reserved count/bytes, `receipt`, `cleanupLease`, `tombstoneUntilMs`. `receipt` is present only when submitted. Rules compare `expiresAtMs` with `request.time.toMillis()`; API may display an ISO rendering of it. Submission queries only active intents, which are bounded by the 5 active attachment limit; scheduled cleanup pages through cancelled intents.
- `feedbackAttachmentIntentDocumentSchema`: reservation identity and exact MIME/bytes, status (`reserved`, `finalizing`, `ready`, `cancelled`), ISO audit timestamps, `lease`, `verified`, `cleanupPending`, and `cleanupAfterMs`. `lease` is present only while finalizing; `verified` is present only when ready. Pending cleanup always has a numeric due time; a cancelled in-flight copy remains pending after immediate deletion until a delayed retry can catch a late copy. `feedbackAttachmentDescriptorSchema` is the verified report-safe metadata: ID, name, canonical `storagePath`, MIME, bytes, object generation string. Never store a signed URL or download token.
- `feedbackActivityDocumentSchema`: append-only `submitted`, `resolved`, `reopened`, `archived`, `unarchived`, or private `note`, with actor, ISO timestamp, optional reason, note, and idempotency request ID. `feedbackThrottleDocumentSchema` holds owner, a sorted bounded `submittedAtMs` array (at most 10), and audit timestamp. The service prunes timestamps older than one rolling hour before appending a first successful submission. Persisted schemas are strict; malformed records fail closed.

All timestamps are UTC `Date#toISOString()` values except numeric expiry/window millisecond fields used by rules and transaction comparisons. Firestore documents must stay below the repository's 900 KiB margin. Attachments are descriptors only, so no media bytes enter Firestore.

## API result shapes

- Session create/get: `feedbackSessionResponseSchema` (`{ session: { id, status, expiresAtMs, receipt, attachments } }`). Public attachments expose only ID, original name, MIME, reserved bytes and state; leases, canonical paths and generations stay server-only. Submit/replay: `feedbackSubmitResponseSchema` (`{ receipt: { feedbackId, submittedAt } }`). Reserve: `feedbackReserveAttachmentResponseSchema` (`{ attachment, stagingPath }`); finalize: `feedbackFinalizeAttachmentResponseSchema` (`{ attachment }`). Removal can return the same attachment shape.
- Admin list query: `feedbackAdminListQuerySchema`; defaults unresolved, nonarchived, newest. Exactly 25 items maximum per response, `{ items, nextCursor }`. Cursor encoding and index selection stay server-owned. Direct ID lookup uses `feedbackId`; email and UID filters are exact. Count result: `{ count }`; detail: `{ feedback }`.
- Admin state mutation: `{ action: 'resolve' | 'reopen' | 'archive' | 'unarchive', expectedRevision, reason? }`. Private note: `{ requestId, note }`. Activity pagination: `{ items, nextCursor }`. Media access: `{ url, expiresAt }`, private/no-store route response.
- Domain errors should use stable `FEEDBACK_ERROR_CODES` with `status`, mapped by `createRouteErrorResponse`; invalid persisted data is `FEEDBACK_INVALID_DOCUMENT`/409, stale lesson is `FEEDBACK_STALE_LESSON_CONTEXT`/409, expired session is `FEEDBACK_SESSION_EXPIRED`/409, unfinished uploads are `FEEDBACK_ATTACHMENT_NOT_READY`/409, report rate limit is `FEEDBACK_REPORT_QUOTA`/429, and stale admin state is `FEEDBACK_REVISION_CONFLICT`/409.

The service must derive UID, identity, timestamps, lesson snapshots, report status, storage paths, verified attachment descriptors, and activity attribution. Submission performs all reads before any writes in one transaction and returns the persisted receipt on retry.
